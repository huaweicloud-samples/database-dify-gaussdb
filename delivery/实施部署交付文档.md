## 二、部署前提

### 2.1 环境要求

- **Docker**：20.10+（含 docker compose v2）
- **GaussDB**：客户已有实例（V2.0+，O模式/DBCOMPATIBILITY='A'），已创建好数据库（如 `dify`）并授权用户
- **网络**：部署机能访问 GaussDB 实例端口（如 19995）；能拉取官方镜像（redis/nginx/web 等，国内建议配镜像加速）
- **资源**：建议 4核8G+（dify 全套服务）；磁盘 20G+

### 2.2 GaussDB 实例准备（客户/DBA 侧）

```sql
-- 1. 创建数据库（若未创建）
CREATE DATABASE dify DBCOMPATIBILITY='A';
-- 注意：必须 O模式（DBCOMPATIBILITY='A'），dify 适配基于此

-- 2. 创建用户并授权（若未创建）
CREATE USER dify_user PASSWORD '<密码>';
GRANT ALL PRIVILEGES ON DATABASE dify TO dify_user;

-- 3. 确认向量扩展（向量库功能需要）
-- 在 dify 数据库下执行：
SELECT * FROM pg_extension WHERE extname = 'vector';
-- 若无，需联系 DBA 启用向量能力（GaussDB 高级特性 License，见 GaussDB 文档）

-- 4. 确认实例类型（影响向量维度上限）
SELECT count(*) FROM pgxc_node WHERE node_type='D';
-- 0 = 集中式（支持 ≤4096 维）；>0 = 分布式（≤1024 维硬限）
```

### 2.3 部署机 Docker 配置（国内建议）

配置 Docker 镜像加速（拉官方镜像用），编辑 `/etc/docker/daemon.json`：
```json
{
  "registry-mirrors": ["https://docker.1ms.run", "https://docker.m.daocloud.io"]
}
```
重启 Docker：`systemctl restart docker`

## 三、部署步骤

### 步骤 1：加载自定义镜像

```bash
# 将交付包放到部署机（假设放 /opt/dify-gaussdb/）
mkdir -p /opt/dify-gaussdb
cd /opt/dify-gaussdb
# 上传交付包文件到此目录

# 加载镜像（约 1-2 分钟）
docker load -i dify-api-gaussdb-1.16.1.tar

# 确认镜像
docker images dify-api-gaussdb:1.16.1
# 应显示：dify-api-gaussdb   1.16.1   <image-id>   1.49GB
```

### 步骤 2：准备配置文件

**部署目录结构**（`.env` 必须和 `docker-compose.yaml` 在同一目录，docker compose 默认读同目录的 `.env`）：

```
/opt/dify-gaussdb/                  ← 部署目录（所有文件放这里）
├── docker-compose.yaml             ← 从交付包复制
├── .env                            ← 从 .env.gaussdb.example 复制并修改
├── dify-api-gaussdb-1.16.1.tar     ← 镜像（docker load 后可删）
├── .env.gaussdb.example            ← 配置模板（参考，可留）
└── 实施部署交付文档.md / 测试指南.md  ← 文档（参考，可留）
```

> **注意**：docker-compose.yaml 中引用了 `./envs/core-services/*.env` 等文件，但都是 `required: false`（缺了不报错），所有配置通过根目录 `.env` 即可覆盖，**不需要 envs/ 目录**。

```bash
cd /opt/dify-gaussdb

# 从交付包复制 compose 文件和配置模板到部署目录
cp docker-compose.yaml ./docker-compose.yaml
cp .env.gaussdb.example .env        # .env 必须在部署目录根（和 compose 同级）

# 编辑 .env，填入实际配置（必改项见下方）
vi .env
```

**.env 必改配置项**（参照 `.env.gaussdb.example`）：

```properties
# 1. 密钥（必填，用 openssl rand -hex 32 生成）
SECRET_KEY=<随机32字符+>
INIT_PASSWORD=<初始化管理员密码>

# 2. 访问地址（改成部署机实际 IP/域名，走 nginx 端口80不带端口号）
CONSOLE_API_URL=http://<部署机IP>
CONSOLE_WEB_URL=http://<部署机IP>
SERVICE_API_URL=http://<部署机IP>
APP_API_URL=http://<部署机IP>
APP_WEB_URL=http://<部署机IP>

# 3. GaussDB 关系库（客户实例）
DB_TYPE=gaussdb
DB_HOST=<GaussDB-IP>
DB_PORT=<GaussDB-端口，如19995>
DB_USERNAME=<用户名>
DB_PASSWORD=<密码>
DB_DATABASE=dify

# 4. GaussDB 向量库（通常与关系库同实例）
VECTOR_STORE=gaussdb
GAUSSDB_HOST=<GaussDB-IP>
GAUSSDB_PORT=<GaussDB-端口>
GAUSSDB_USER=<用户名>
GAUSSDB_PASSWORD=<密码>
GAUSSDB_DATABASE=dify
GAUSSDB_INDEX_TYPE=ivffflat    # ≤1024维用ivfflat；>1024维用diskann
```

**关于 GAUSSDB_INDEX_TYPE 选择**：
- `ivfflat`：≤1024 维，适合小数据量（1万~200万向量），查询快
- `diskann`：大数据量；>1024 维必须用 diskann（自动启用 PQ 降维，集中式支持到 4096 维）
- 分布式 GaussDB 无论哪种索引都限 1024 维（建表硬限）

### 步骤 3：启动服务

```bash
cd /opt/dify-gaussdb

# 启动全部服务（后台），首次会拉取 redis/nginx/web 等官方镜像
docker compose up -d

# 查看启动状态
docker compose ps
# 等待 api 服务 healthy（约 1-3 分钟，首次会跑数据库迁移建表）
```

**首次启动说明**：
- `MIGRATION_ENABLED=true` 时，api 服务启动前自动执行 `flask upgrade-db`（在 GaussDB 建全部表，约 88 个迁移）
- 迁移完成后 gunicorn 启动，`/health` 可访问
- 迁移只需首次执行；后续重启若 schema 已最新则跳过（alembic 检测到 head）

### 步骤 4：验证部署

```bash
# 1. API 健康检查（api 容器内）
docker compose exec api curl -s http://localhost:5001/health
# 应返回：{"pid":xx,"status":"ok","version":"1.16.1"}

# 2. 从部署机访问（通过 nginx，端口 80）
curl -s http://localhost/health
curl -s http://localhost/console/api/setup
# 应返回：{"step":"not_started","setup_at":null}

# 3. 浏览器访问控制台
# 打开 http://<部署机IP>，应显示 Dify 初始化页面
```

### 步骤 5：初始化 Dify（首次使用）

1. 浏览器访问 `http://<部署机IP>`
2. 首次访问会要求输入初始化密码（即 `.env` 中的 `INIT_PASSWORD`）
3. 设置管理员账号（邮箱 + 密码 + 名称）
4. 登录后即可使用 Dify

## 四、配置说明

### 4.1 docker-compose.yaml 镜像替换

交付的 `docker-compose.yaml` 已将 4 处官方镜像替换为自定义镜像：

| 服务 | 原镜像 | 替换后 |
|---|---|---|
| api | langgenius/dify-api:1.16.1 | **dify-api-gaussdb:1.16.1** |
| api_websocket | langgenius/dify-api:1.16.1 | **dify-api-gaussdb:1.16.1** |
| worker | langgenius/dify-api:1.16.1 | **dify-api-gaussdb:1.16.1** |
| worker_beat | langgenius/dify-api:1.16.1 | **dify-api-gaussdb:1.16.1** |

其他服务（web/redis/sandbox/plugin_daemon/agent_backend/nginx）用官方镜像，不改。

### 4.2 服务架构

```
                    ┌─────────┐
   用户 ──80/443──→ │  nginx  │ ──→ web:3000（前端）
                    └────┬────┘
                         ├──→ api:5001（HTTP API，gunicorn）
                         ├──→ api_websocket:5001（协同编辑）
                         └──→ plugin_daemon:5002（插件）
                    
   api/worker ──→ redis:6379（缓存 + celery broker）
   api/worker ──→ GaussDB（关系库 + 向量库，外部实例）
   worker ──→ celery（消费 dataset/workflow/mail 等队列）
   worker_beat ──→ celery beat（定时任务）
   agent_backend ──→ local_sandbox + ssrf_proxy（Agent 沙箱）
```

### 4.3 关键配置项说明

| 配置 | 说明 | 默认/建议 |
|---|---|---|
| `DB_TYPE=gaussdb` | 关系库类型，底层用 opengauss+psycopg2 方言 | 必填 gaussdb |
| `VECTOR_STORE=gaussdb` | 向量库类型，用 vdb-gaussdb adapter | 必填 gaussdb |
| `GAUSSDB_INDEX_TYPE` | 向量索引类型 ivfflat/diskann | 按维度选 |
| `MIGRATION_ENABLED` | 启动时是否自动迁移 | 首次 true，之后可 false |
| `COMPOSE_PROFILES` | compose 服务 profile | gaussdb,gaussdb,collaboration（不改） |
| `SECRET_KEY` | JWT/session 签名密钥 | 必填，≥32字符 |
| `INIT_PASSWORD` | 初始化密码 | 建议填 |

### 4.4 GaussDB 不启动容器化数据库

`DB_TYPE=gaussdb` + `VECTOR_STORE=gaussdb` 时，`COMPOSE_PROFILES=gaussdb,gaussdb,collaboration`。由于 compose 中没有 `gaussdb` profile 的服务，**不会启动 db_postgres/weaviate 等内置数据库容器**——这是正确的，GaussDB 是外部实例，关系库和向量库共用。

## 五、运维操作

### 5.1 常用命令

```bash
cd /opt/dify-gaussdb

# 查看服务状态
docker compose ps

# 查看日志
docker compose logs -f api          # api 日志
docker compose logs -f worker       # worker 日志
docker compose logs -f --tail 100   # 全部日志最近100行

# 重启服务
docker compose restart api
docker compose restart              # 重启全部

# 停止/启动
docker compose down                 # 停止并删容器（数据卷保留）
docker compose up -d                # 重新启动

# 手动跑迁移（不重启服务）
docker compose exec api flask upgrade-db

# 查看迁移版本
docker compose exec api flask db current
```

### 5.2 数据库迁移

- **首次部署**：`MIGRATION_ENABLED=true`，api 启动时自动建表
- **升级 dify 版本**：拉新镜像 + `MIGRATION_ENABLED=true` 重启 api，自动跑增量迁移
- **手动迁移**：`docker compose exec api flask upgrade-db`

### 5.3 备份

- **GaussDB 数据**：由 DBA 按 GaussDB 备份策略执行（pg_dump 或 GaussDB 工具）
- **Redis 数据**：compose 自带 redis 卷（`./volumes/redis/data`）
- **存储文件**：`./volumes/app/storage`（上传的文件、知识库数据等）

## 六、故障排查

### 6.1 api 启动失败

```bash
# 查 api 日志
docker compose logs api | tail -50

# 常见原因：
# 1. GaussDB 连不上 → 检查 DB_HOST/PORT/USERNAME/PASSWORD，部署机能否 telnet GaussDB 端口
# 2. 迁移失败 → 查日志里的迁移报错，可能 GaussDB O模式兼容问题（见测试指南已知限制）
# 3. Redis 连不上 → 检查 redis 容器是否启动：docker compose ps redis
```

### 6.2 GaussDB 连接问题

```bash
# 测试连通性
docker compose exec api python -c "
import psycopg2
conn = psycopg2.connect(host='<GaussDB-IP>', port=<端口>, user='<用户>', password='<密码>', dbname='dify')
cur = conn.cursor()
cur.execute('select 1')
print('GaussDB 连接成功:', cur.fetchone())
"

# 确认 O模式
docker compose exec api python -c "
import psycopg2
conn = psycopg2.connect(host='<GaussDB-IP>', port=<端口>, user='<用户>', password='<密码>', dbname='dify')
cur = conn.cursor()
cur.execute(\"SELECT datcompatibility FROM pg_database WHERE datname='dify'\")
print('DBCOMPATIBILITY:', cur.fetchone())  # 应为 ('A',)
"
```

### 6.3 向量库问题

- 创建知识库/上传文档时报错 → 查 `GAUSSDB_INDEX_TYPE` 与 embedding 维度是否匹配
- embedding 维度 > 1024 但 `GAUSSDB_INDEX_TYPE=ivfflat` → 改为 `diskann`
- 分布式 GaussDB + >1024 维 → 无法支持（分布式硬限 1024，需降维或换集中式）

### 6.4 nltk 数据缺失

镜像已预装 nltk 数据（punkt/punkt_tab/averaged_perceptron_tagger/stopwords）。若分词报错：
```bash
# 确认 nltk 数据
docker compose exec api python -c "
import nltk
print(nltk.data.find('tokenizers/punkt_tab'))
"
```

## 七、GaussDB 适配技术说明（供参考）

### 7.1 关系库适配

- **方言**：`opengauss+psycopg2`（opengauss-sqlalchemy 2.4.0），`DB_TYPE=gaussdb` 时自动启用
- **O模式空串→NULL 补丁**：`ext_database.py` 的 `_patch_opengauss_empty_string()`，用 SQLAlchemy `before_cursor_execute` 事件把空串 `''` 转空格 `' '`（O模式把空串当 NULL，dify 有 19+ 处 `default="" + NOT NULL` 列会冲突）
- **inspector 补丁**：`_patch_opengauss_inspector()`，用 information_schema.columns 替代 pg_catalog（GaussDB pg_catalog 查询报 FROM-clause 错误）
- **迁移**：88 个迁移的 `_is_pg` 判断在 opengauss 方言下走 else 分支，5 个空串迁移已修补

### 7.2 向量库适配

- **adapter**：`dify-vdb-gaussdb`（`providers/vdb/vdb-gaussdb/`），实现 BaseVector 9 个方法
- **类型**：floatvector(dim)，cosine 距离 `<+>`，score = 1 - distance
- **索引**：GsIVFFLAT（≤1024维）/ GsDiskANN（>1024维自动 PQ 降维，集中式≤4096）
- **全文检索**：BM25 索引优先，失败降级 tsvector
- **建索引内存**：GsDiskANN 时 SET maintenance_work_mem='512MB'

### 7.3 镜像构建说明

镜像因 Docker Desktop WSL2 环境限制，采用「docker run + bind mount uv cache + docker commit」分步构建（标准 `docker build` 在该环境有 I/O 问题）。**正式 CI/生产重建应在 Linux 机器执行 `docker build`**，Dockerfile 已就绪（`api/Dockerfile` + `api/Dockerfile.production`）。
