## 二、脚本配置说明（重要）

**所有脚本自动读 GaussDB 连接配置，无需手动修改脚本内的连接信息**。配置来源分两种场景：

### 场景 A：在 api 容器内执行（L2/L4/L5 脚本）

docker compose 启动时，`env_file: .env` 会把部署目录 `.env` 的变量**注入容器环境变量**（`os.environ`），不是挂载文件。所以：

- api 容器内**没有 `.env` 文件**，但 `os.environ` 有 `DB_HOST`/`GAUSSDB_*`/`REDIS_*` 等变量
- 脚本的 `load_env()` 用 `os.environ.setdefault()`——环境变量已有值时不覆盖，**自动读 compose 注入的值**
- 容器内执行脚本前，需先把脚本复制进容器或挂载：
  ```bash
  # 方式1：复制 tests/ 进 api 容器
  docker compose cp tests/ api:/app/api/tests/
  docker compose exec api python /app/api/tests/e2e_vector_test.py

  # 方式2：挂载（在 docker-compose.yaml 的 api 服务加 volume，推荐调试用）
  # volumes:
  #   - ./tests:/app/api/tests
  ```

### 场景 B：在部署机执行（L3 的 e2e_crud_test.sh）

`e2e_crud_test.sh` 从部署目录 `.env` 读 `INIT_PASSWORD` + `CONSOLE_API_URL`。脚本默认从 `../.env` 读（即 tests/ 的上级目录）。

**部署目录结构**（.env 和 docker-compose.yaml 同级）：
```
/opt/dify-gaussdb/              ← 部署目录（cd 到这里执行）
├── docker-compose.yaml
├── .env                        ← 配置文件（脚本读这个）
└── tests/                      ← 测试脚本目录
    └── e2e_crud_test.sh        ← 从 ../.env 读配置
```

```bash
cd /opt/dify-gaussdb
bash tests/e2e_crud_test.sh                 # 从 ../.env 读
bash tests/e2e_crud_test.sh 192.168.1.100   # 或传部署机IP
```

### 自定义 .env 路径

若 .env 不在默认位置，用 `ENV_FILE` 环境变量指定：
```bash
# 容器内
docker compose exec api sh -c 'ENV_FILE=/custom/.env python /app/api/tests/probe_dim_limit.py'
# 部署机
ENV_FILE=/opt/dify-gaussdb/.env bash tests/e2e_crud_test.sh
```

**前提条件**：
- L2/L4/L5 脚本在 api 容器内执行（需先复制/挂载 tests/ 进容器）
- L4 向量测试需 redis 容器在跑（adapter 用 redis 加锁）
- L3 关系库测试需 api 服务在跑（走 HTTP API，从部署机访问 nginx 端口80）

## 五、L3 关系库 CRUD 端到端（HTTP API）

### 5.1 测试流程

`e2e_crud_test.sh` 自动执行完整流程：
```
GET  /console/api/init        → 查初始化状态
GET  /console/api/setup       → 查 setup 状态
POST /console/api/init        → 验证 INIT_PASSWORD（明文）
POST /console/api/setup       → 创建 admin + tenant（明文密码）
POST /console/api/login       → 登录（base64 密码，拿 cookie + csrf_token）
GET  /console/api/apps        → 查询 apps（带 CSRF header）
POST /console/api/apps        → 创建 app（写库）
GET  /console/api/apps/{id}   → 查询创建的 app（读一致性）
DELETE /console/api/apps/{id} → 删除 app
```

### 5.2 执行

```bash
# 在部署机执行（api 服务需在跑）
cd /path/to/delivery/tests
bash e2e_crud_test.sh
# 或指定部署机IP（默认从 .env 的 CONSOLE_API_URL 读）
bash e2e_crud_test.sh 192.168.1.100
```

### 5.3 关键机制（脚本已处理，了解即可）

| 点 | 说明 |
|---|---|
| **login 密码 base64** | login 有 `@decrypt_password_field` 装饰器，password 必须 base64 编码；脚本自动 `echo -n 密码 \| base64` |
| **setup 密码明文** | setup 无此装饰器，传明文 |
| **CSRF token** | login 后 cookie 有 `csrf_token`，脚本自动提取并加 `X-CSRF-Token` header |
| **测试数据清理** | 脚本创建的 app 会自动删除；admin 账号需手动清理（见 5.5） |

### 5.4 预期结果

| 步骤 | 预期 |
|---|---|
| init | `{"status":"not_started"}` |
| setup(POST) | `{"result":"success"}` |
| login | `{"result":"success"}` |
| 查询 apps | `{"total":0,"data":[]}` |
| 创建 app | `{"id":"<uuid>","name":"E2E-Test-App",...}` |
| 查询 app | 读回创建的 app，id/name 一致 |
| 删除 app | 200/204 |

### 5.5 测试后清理 admin 账号

脚本会删除创建的 app，但 admin 账号需手动清理（避免污染）：

```bash
docker compose exec api python -c "
import os, psycopg2
ENV_FILE = '../.env'
for line in open(ENV_FILE):
    line = line.strip()
    if line and not line.startswith('#') and '=' in line:
        k, v = line.split('=', 1); os.environ.setdefault(k.strip(), v.strip())
conn = psycopg2.connect(host=os.environ['DB_HOST'], port=int(os.environ['DB_PORT']),
    user=os.environ['DB_USERNAME'], password=os.environ['DB_PASSWORD'], dbname=os.environ['DB_DATABASE'])
cur = conn.cursor()
EMAIL='e2e-test-admin@example.com'
cur.execute('SELECT id FROM accounts WHERE email=%s', (EMAIL,))
row = cur.fetchone()
if row:
    aid = row[0]
    cur.execute('SELECT tenant_id FROM tenant_account_joins WHERE account_id=%s', (aid,))
    tids = [r[0] for r in cur.fetchall()]
    cur.execute('DELETE FROM tenant_account_joins WHERE account_id=%s', (aid,))
    cur.execute('DELETE FROM accounts WHERE id=%s', (aid,))
    for tid in tids: cur.execute('DELETE FROM tenants WHERE id=%s', (tid,))
cur.execute('DELETE FROM sites WHERE title=\"E2E-Test-App\"')
cur.execute('DELETE FROM dify_setups')
conn.commit(); print('清理完成')
"
```
**表名注意**：`tenant_account_joins`（不是 tenant_members）、`dify_setups`（不是 dify_setup）。

### 6.5 索引类型与维度规则

| 索引 | 维度 | 集中式 | 分布式 |
|---|---|---|---|
| IVFFLAT | ≤1024 | ✅ | ✅ |
| DiskANN（无PQ） | ≤1024 | ✅ | ✅ |
| DiskANN+PQ | >1024（≤4096） | ✅ | ❌（硬限1024） |

- `GAUSSDB_INDEX_TYPE=ivfflat`：≤1024 维，小数据量
- `GAUSSDB_INDEX_TYPE=diskann`：大数据量；>1024 维必须（自动 PQ）

## 八、已知限制与注意事项

### 8.1 GaussDB O模式空串→NULL

- **已修复**：镜像含 `before_cursor_execute` patch，自动把空串转空格（`ext_database.py`）
- **验证**：L3 创建 app 后，查 `sites.custom_disclaimer` 应为空格 `' '`（length=1），非 NULL

### 8.2 维度限制

- GsIVFFLAT ≤1024 维；GsDiskANN+PQ 集中式 ≤4096，**分布式硬限 1024**（建表阶段）
- embedding 维度 > 1024 时 `GAUSSDB_INDEX_TYPE` 必须设 `diskann`

### 8.3 表名注意

| dify model 表名 | 说明 |
|---|---|
| `tenant_account_joins` | 不是 `tenant_members` |
| `dify_setups` | 不是 `dify_setup` |

### 8.4 login 密码编码

- login：password 必须 **base64 编码**（脚本已处理）
- setup/init：password **明文**

### 8.5 nltk 数据

镜像已预装 punkt/punkt_tab/averaged_perceptron_tagger/stopwords。nltk 3.9+ 用 `punkt_tab`（新格式）。

### 8.6 分布式 GaussDB

集中式全链路已验证。分布式 GaussDB 的 1024 维硬限 + 部分系统表差异未实测（需分布式实例）。
